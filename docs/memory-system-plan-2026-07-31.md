# 共享记忆系统构想（2026-07-31）

> 状态：**构想，未实现**。本文记录目标、现状事实和可行路径，供后续开工时参考。
> 不要把本文描述的能力写进用户文档或应用内文案。

## 目标

让「每日一言（今日思考）」「周期洞察」「Thoughter Agent 会话」共享同一份用户记忆，
记住用户偏好，而不是每次都从零开始猜。

期望效果举例：

- 用户长期写碎句、不用标题 → agent 生成的提案自然是碎句，不再输出"漂亮的散文段落"。
- 用户多次拒绝"给知识整理类笔记加天气" → 以后这类笔记默认不加。
- 每日提示不再每天问一样的句式，能承接用户最近在意的主题。
- 洞察报告知道用户上次已经看过哪些结论，不重复讲。

## 现状事实（2026-07-31 核查，带 file:line）

### 1. Agent 会话上下文是「持久但严重削减」的

- 消息**会**入库：`chat_messages` 表（`chat_session_service.dart:342-354`），
  从历史会话恢复走 `_loadSession` → `getMessages` → `_messages`
  （`ai_assistant_page_session.dart:214-228`）。**所以重开历史会话，agent 能看到之前的对话文本。**
- 但削减掉了三层：
  1. **工具调用与工具结果完全不入库**。表里只有 role/content/meta_json 等
     （`chat_message.dart:83-95`），没有 tool_calls / tool_result 列。上一轮 agent
     查到了什么、读了哪条笔记、改了什么，下一轮**完全不知道**，只能从助手的自然语言
     正文里猜。
  2. **带 `metaJson` 的消息被整个排除出上下文**
     （`ai_assistant_page_agent.dart:9-11`：`m.metaJson == null`）。也就是说
     所有提案卡片、智能结果卡片在下一轮对模型不可见——agent 不知道自己上轮提过什么方案。
  3. **历史预算只有 4000 字符**，单条截断到 1200 字符
     （`agent_service.dart:863-868` → `ai_request_helper.dart:39-84`）。
     中文下 4000 字符大约只够五六轮短对话。
- `state` / `thinkingChunks` 只存在于 `toJson()`（备份路径），**不写进 SQLite**
  （`chat_message.dart:98-113` vs `:83-95`）。重开会话后思考过程一律消失。

### 2. 没有任何 prompt 缓存

全仓库无 `cache_control` / prompt caching 用法。每轮把 system prompt（约 2000 字）
+ 历史重新完整发一遍。对按 token 计费的 provider 是纯浪费；ollama.com 目前无感。

### 3. 每日一言与洞察完全无状态

`streamGenerateDailyPrompt` 每次只带城市/天气/气温 + `historicalInsights`
（`ai_service.dart:463-537`）。除了洞察历史，不知道用户任何偏好。

## 可行路径（草案）

分三层，可以独立推进，不必一次做完：

### L1 事件层（最先做，成本最低）

把已经发生但被丢掉的信号记下来，不做任何推断：

- 提案被采纳 / 被忽略（现在 `saved_note_id`、`applied` 已经写在 metaJson 里，但只用于 UI）
- 用户在提案卡片上手动改了哪些字段（改标签、去掉天气 → 强信号）
- 每日提示是 AI 生成还是走了本地兜底

落库到新表 `user_signals(id, kind, payload_json, created_at)`。这一层没有 AI 参与，
纯记录，风险低。

### L2 偏好层

定期（或达到 N 条信号时）把 L1 汇总成一份短的、人类可读的偏好档案，例如：

```
- 写作篇幅：偏短，常在 30-80 字，少用标题
- 标签：复用已有标签，几乎不新建
- 元数据：日常片段接受位置天气；知识整理类多次手动去掉天气
```

存成单条文本（几百字以内），三个功能共用。**必须让用户能看见和编辑**——这是
用户自己的画像，不能是黑箱。

### L3 注入层

- Agent：作为 system prompt 后的一条独立 `user` 数据消息注入（和绑定笔记的做法一致，
  不要塞进 system prompt，避免和不可信数据混淆）。
- 每日提示 / 洞察：拼进现有的 system prompt 上下文。

## 已知的坑

- **隐私**：偏好档案是对用户的行为画像，必须只存本地、进备份、可一键清空。
  不得随任何遥测外发。
- **不要做成"AI 猜用户是什么人"**：只记可观测的写作习惯，不记性格、情绪、健康等推断。
- L2 如果用 AI 生成，要考虑失败降级（生成失败就沿用旧档案，不能清空）。
- 与 `insight_history_service` 有重叠，动手前先看它现在存了什么，避免造第二套。

## 前置依赖

L1 之前建议先解决 Agent 会话上下文的三层削减（见「现状事实 1」），否则记忆系统
会建在一个每轮失忆的框架上，收益会被稀释。
